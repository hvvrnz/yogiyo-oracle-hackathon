# 실제 통합 시연 데이터 세트

이 문서는 실제 DB를 변경하지 않는 조회 전용 통합 시연에 사용하는 고정 ID를 기록한다.

## 패널 구성

| 역할 | ID | 연결 패키지 | 확인 경로 |
| --- | --- | --- | --- |
| 고객 | 주문 `118` | 패키지 `740` | 매장 `781`, 라이더 `rider_102` |
| 사장님 | 매장 `781` | 패키지 `740` | 주문 `118`, 라이더 `rider_102` |
| 사장님 | 매장 `467` | 패키지 `638` | 주문 `184`, 라이더 `rider_103` |
| 사장님 | 매장 `273` | 패키지 `635` | 주문 `226`, 라이더 `rider_105` |
| 라이더 | `rider_102` | 패키지 `740` | 주문 `118`, 매장 `781` |
| 라이더 | `rider_103` | 패키지 `638` | 주문 `184`, 매장 `467` |
| 라이더 | `rider_105` | 패키지 `635` | 주문 `226`, 매장 `273` |

각 패키지는 현재 `MATCHING`, 연결 주문은 `MATCHED` 상태로 조회됐다. 데이터는 공유 DB 상태에 따라 바뀔 수 있으므로 시연 직전에 아래 조회를 다시 확인한다.

```text
GET /api/customer/118
GET /api/merchant/781
GET /api/merchant/467
GET /api/merchant/273
GET /api/rider/rider_102
GET /api/rider/rider_103
GET /api/rider/rider_105
```

## 읽기 전용 시연 원칙

- 이 세트의 실제 DB 상태는 프론트 검증 과정에서 변경하지 않는다.
- 실제 모드 통합 시연은 조회·5초 폴링만 수행한다.
- 취소, 조리시간 변경, 패키지 픽업/완료 동작은 `VITE_USE_MOCK=true`에서 먼저 검증한다.
- 실제 상태 변경 시연은 별도로 제공된 재현/초기화 가능한 테스트 DB가 준비된 뒤 수행한다.
