## 프로젝트 개요

요기요 × Oracle Hackathon — 조리시간 인지 기반 배달 시퀀싱 백엔드.
현재 초기 스캐폴드 단계이며, 대부분의 소스 파일이 완성된 상태

## 최상위 규칙 — 모든 작업은 사전 승인제

- **어떤 종류의 작업이든(파일 생성/수정/삭제, 명령 실행, OCI 리소스 조작 등)
  실행하기 전에 반드시 사용자에게 먼저 무엇을 왜 하려는지 설명하고 승인을 받는다.**
  승인 없이 먼저 실행하고 나중에 보고하는 방식은 금지한다.

- 승인을 구할 때는 다음을 반드시 포함해서, 비전공자도 이해할 수 있을 만큼
  아주 자세하고 꼼꼼하게 설명한다:
  1. 무엇을 하려는 것인지 (실행할 명령어 또는 변경할 파일)
  2. 왜 이 작업이 필요한지 (목적, 배경)
  3. 이 명령/개념이 정확히 무엇을 의미하는지 (예: 이 옵션은 무슨 뜻인지,
     이 API가 무슨 역할을 하는지)
  4. 실행했을 때 어떤 결과가 예상되는지
  5. 실패하거나 잘못됐을 때 어떤 위험이 있는지
- 조회성 명령(list, get, describe, status, cat, ls 등 읽기 전용)이라도
  생략하지 말고 위 원칙에 따라 먼저 설명하고 승인을 받은 뒤 실행한다.
- 사용자가 승인하지 않거나 답이 없으면 절대 실행하지 않는다.

## OCI CLI 작업 규칙

- OCI CLI로 작업할 때는 반드시 아래 compartment-id만 사용한다:
  `ocid1.compartment.oc1..aaaaaaaalrs7svywbzhe4uizalih4nmy7a2v4myrrd7mxwljutbc5tmrkp5a`
- 다른 compartment의 리소스를 조회하거나 수정하는 명령은 실행하지 않는다.
- 리소스를 생성(create), 수정(update), 삭제(delete)하는 명령은 특히 더 신중하게,
  실행 전 반드시 위의 "최상위 규칙"에 따라 상세히 설명하고 승인받는다.
- Autonomous Database(ADB) 생성 시 반드시 developer 옵션(Always Free가 아닌
  개발자용 저사양)으로 생성한다.

## 코드 작업 규칙

- 다른 팀원(준영)의 작업 폴더(`../ygy-frontend` 또는 `ygy-frontend-only` 등)는
  건드리지 않는다.
- 이 폴더(`ygy-backend`) 밖의 파일은 명시적으로 요청받지 않는 한 수정하지 않는다.
