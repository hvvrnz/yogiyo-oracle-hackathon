# 지도 및 경로 전략 확장

## 1. 경로 전략

기존 `혼합 최적화` 경로를 삭제하거나 변경하지 않았습니다. 시연 콘솔에서 다음 두 전략을 선택할 수 있도록 확장했습니다.

### 혼합 최적화 (`optimized`)

- 기존 데모의 기본값입니다.
- 픽업과 배달을 섞어서 수행할 수 있습니다.
- 조리 완료 예상시각, 라이더 대기시간, 가방 체류시간, ETA, 총 이동시간을 함께 비교합니다.
- 현재 시연 경로: `픽업 → 픽업 → 배달 → 픽업 → 배달 → 배달`

### 전체 픽업 후 배달 (`pickup_first`)

- 세 매장의 픽업을 모두 완료한 뒤 배달을 시작합니다.
- 현재 시연 경로: `픽업 → 픽업 → 픽업 → 배달 → 배달 → 배달`
- 모든 주문에서 `해당 주문 픽업이 해당 주문 배달보다 먼저 수행`되는 제약을 유지합니다.
- 가방 체류시간과 고객 ETA 기준을 통과하는 경우에만 사용할 수 있다는 전제를 데이터에 반영했습니다.

### 전환 방법

`/demo`의 다음 버튼을 사용합니다.

- `혼합 최적화`
- `전체 픽업 후 배달`

API를 직접 호출할 수도 있습니다.

```http
POST /api/demo/route-strategy
Content-Type: application/json

{"strategy":"pickup_first"}
```

운행 단계가 하나라도 완료된 뒤에는 경로 전략을 바꿀 수 없습니다. 이미 픽업하거나 배달한 단계를 되돌려 데이터가 모순되는 상황을 막기 위한 제한입니다.

## 2. 지도 제공자

고객·라이더 지도는 세 가지 모드를 지원합니다.

| 값 | 동작 |
|---|---|
| `naver` | 네이버 지도 JavaScript API 사용 |
| `google` | Google Maps JavaScript API 사용 |
| `demo` | 기존 시연용 추상 지도 사용 |

기본값은 `naver`입니다. 키가 비어 있거나 SDK 로딩에 실패하면 기존 시연용 지도로 자동 복귀합니다. 따라서 외부 지도 설정이 잘못되어도 주문·조리·배차·WebSocket 기능은 영향을 받지 않습니다.

### 네이버 지도 설정

`.env`:

```env
MAP_PROVIDER=naver
NAVER_MAPS_NCP_KEY_ID=발급받은_ncpKeyId
```

네이버 클라우드 Maps 애플리케이션에 로컬 및 배포 주소를 허용 URL로 등록해야 합니다.

예시:

```text
http://127.0.0.1:8000
http://localhost:8000
https://배포도메인
```

### 구글 지도 설정

`.env`:

```env
MAP_PROVIDER=google
GOOGLE_MAPS_API_KEY=발급받은_API_KEY
```

Maps JavaScript API를 활성화하고 API Key에 HTTP 리퍼러 제한을 적용합니다.

### 기존 지도 강제 사용

```env
MAP_PROVIDER=demo
```

## 3. 지도에 표시되는 정보

### 고객 지도

- 고객이 주문한 매장
- 고객 본인의 배달지
- 라이더 현재 위치
- 비식별화된 다른 매장과 배달지
- 현재 선택된 방문 순서

다른 고객의 좌표는 고객 API에서 반올림된 값만 전달합니다.

### 라이더 지도

- 전체 픽업·배달 경유지
- 라이더 현재 위치
- 현재 선택된 경로 순서
- 배차 수락 전에는 상세 고객 주소 비공개

## 4. 카카오모빌리티 길찾기 연동 시

현재 실제 지도 위 경로선은 시연 데이터의 경유지 좌표를 순서대로 연결합니다. 추후 `common/providers.py`의 `RoutingProvider`를 카카오모빌리티 길찾기 구현체로 교체하면 다음 값을 사용할 수 있습니다.

- 실제 도로 기준 구간 거리
- 실제 도로 기준 예상 이동시간
- 도로 형상을 따르는 polyline 좌표

지도 제공자와 길찾기 제공자는 분리되어 있습니다. 예를 들어 네이버 지도 위에 카카오모빌리티에서 받은 경로 polyline을 그리는 구성이 가능합니다.
